

NOTE:

Make minimal changes! Do not change parts of the code that you were not instructed to touch. Think about the request and find the minimal set of changes that satisfy the request.

Please print out only the changed files, not all files, only those that you have changed. And please do provide a short summary/comment that summarizes the changes in the diffs that follow.

Avoid adding dependencies unless you have to, but balance this with having to write a lot of "one-time" code. Eg when doing simple HTML parsing, maybe avoid a dependency, but add a comment to revise later if needed. Heed these comments and suggest rewriting code if it becomes too large (but only suggest! don't just rewrite it).

Do not add comments like "FIX: ..." that describe what was fixed in _this step_/session, they will be obsolete soon enough and just clutter the file. Only add comments describing long-term pre-conditions, explaining the code as-written and so on.

Print blocks of changes as diffs. We use a special diffing format to automatically apply changes. Diffs cannot be grouped, every single diff needs the full header and end marker. Diffs require both the prologue, the triple quotes ("````") around the content and the epilogue.

Format every diff block the following way:

"
#>>>>> {full filename and path as passed in}
```
{full original text section that will be replaced. print the full section verbatim here!}
#=====
{changes to replace the above section with}
```
#<<<<< end
"

For example:

"
#>>>>> config.yaml
```
system:
  theme: light
#=====
system:
  theme: dark
```
#<<<<< end
"

When creating a new file, omit the "#=====" divider and "original part" entirely.

#>>>>> new_file.tzt
```
This would be what an entirely new file looks like, no "original" above and no divider!
```
#<<<<< end
"

Use diffs to make smaller changes to contiguous sections of files, when changing most of a file or making many scattershot changes prefer to print the whole file. The diff format is important as we use automated tools to apply these, please stick to the format, otherwise the diffs cannot be applied and will fail.

Before printing the diffs, provide a short summary of the changes and a very short reason for making them.
